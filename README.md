# Адаптивная логистика

Локальная программа для логиста перевозчика. Она показывает, как рыночный шок меняет экономику обычных рейсов с возвратом на базу, и предлагает другой план той же смены: связать заказы в цепочку, выбрать свою машину или подрядчика.

Все суммы считает сервер. Экран их не придумывает. Заказы, расстояния и тарифы в демонстрации синтетические: это учебная сеть, не история реальной компании и не прогноз рынка.

Лицензия репозитория не выбрана.

## Что понадобится

- Windows 10 или 11
- Python 3.11
- Node.js 20.19+ или 22+. Проверено на Node.js 24.20.0 и npm 11.19.0
- Свободные порты 8000 и 5173

После установки Node.js откройте **новое** окно PowerShell. В старом окне команда `npm` может быть «не распознана».

## Установка

В PowerShell перейдите в папку проекта и выполните команды по порядку.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements-dev.lock
npm ci --prefix frontend
```

`npm ci` ставит версии из `frontend/package-lock.json`. Первая установка Python-пакетов скачивает их из интернета. После этого расчёт и страница работают локально.

Если `py -3.11` не находится, установите Python 3.11 с python.org и отметьте «Add python.exe to PATH». Если `npm` не находится в новом окне, установите Node.js LTS и снова откройте терминал.

## Запуск

Нужны два процесса. Окно, в котором запущена команда, не закрывайте.

**Окно 1. Расчётный сервер**

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

Дождитесь строки `Uvicorn running on http://127.0.0.1:8000`.

**Окно 2. Интерфейс**

```powershell
npm --prefix frontend run dev
```

Дождитесь строки `Local: http://127.0.0.1:5173/`.

Откройте в браузере именно этот адрес: [http://127.0.0.1:5173/](http://127.0.0.1:5173/). Адрес `localhost` без цифр может открыть другую страницу, если интерфейс слушает только IPv4.

Остановить сервер: в его окне нажмите Ctrl+C.

### Если страница не открывается

- Команда `uvicorn` пишет, что адрес уже используется. Сервер уже запущен. Откройте http://127.0.0.1:5173/ и не стартуйте второй экземпляр на порту 8000.
- `npm` не распознан. Закройте терминал, откройте новый и повторите команду из папки проекта.
- Браузер пишет, что соединение отклонено. Проверьте, что оба окна ещё работают и в адресе есть `127.0.0.1:5173`.
- Страница открылась, но пишет «Не удалось связаться с расчётным сервисом». Не запущен сервер из первого окна либо он упал. Запустите его снова и нажмите «Повторить».

### Один адрес без второго окна

Так удобно показывать уже собранную версию. Сборка один раз:

```powershell
npm --prefix frontend run build
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

После сборки страница и API живут вместе: [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Для обычной работы удобнее пара команд выше: интерфейс на 5173 сразу видит правки в коде.

## Как пользоваться

Программа считает одну условную смену. Компания в модели — перевозчик: выручка это плата клиента за перевозку, не стоимость товара в кузове.

На экране три состояния:

| Код | Что это |
|---|---|
| A | Исходные цены и обычная политика: каждый заказ отдельным рейсом с возвратом на базу |
| B | Новые цены, число заказов или доступность. Маршруты те же, если изменились только деньги. Если изменились заказы или ресурсы, та же политика считается заново |
| C | Те же заказы и цены, что в B, но программа ищет цепочки и другой выбор транспорта |

Разница B и A — эффект сценария. Разница C и B — эффект перестройки плана. Процент экономии появляется только если B и C выполнили один и тот же набор заказов. Иначе программа прямо пишет, что это не сопоставимая экономия.

### Короткий показ

1. Откройте «Обзор». Дождитесь цифр. Пока идёт загрузка, на карточках нет нулей: программа ещё не подставляет выдуманный результат.
2. Справа нажмите **«Рост расходов»**. Топливо станет +25%, оплата труда +10%, подрядчики +10%. Старые цифры останутся на экране с пометкой, что это предыдущий расчёт.
3. Нажмите **«Пересчитать влияние»**. Появится B. Результат обычно хуже A, а маршруты те же: машины едут по-старому, но топливо и зарплата дороже. Под топливом будет цена вида «70 → 87,5 ₽/л».
4. Нажмите **«Найти план адаптации»**. Кнопка на время поиска пишет «Ищем допустимые цепочки…». Появится C: другие последовательности заказов, меньше пустых километров и другой расчётный результат. На демонстрационной сети снижение затрат C относительно B около 8,9%, если сервис тот же.
5. В блоке «Изменения плана» откройте цепочку. Для рефрижератора пустой пробег между парой заказов уменьшается на 80 км. Деньги этой одной карточки программа не выдаёт за отдельную экономию: эффект общий по плану.
6. Нажмите **«Недостаточно мощности»**, затем снова **«Найти план адаптации»**. Водитель рефрижератора отключён, подходящей замены нет. Полный план не строится, колонка C не заполняется нулями.

Исходные условия возвращает кнопка **«Сбросить»** в шапке или **«Сбросить изменения»** на панели справа.

### Панель сценария

Справа три группы.

**Расходы.** Топливо от −20% до +60%, оплата труда от 0% до +40%, подрядчики от −10% до +50%. Снижение зарплаты ползунком не предлагается. Шаг 5%. Число можно ввести и с клавиатуры.

**Доходы и спрос.** Тариф клиента от −20% до +10%. Число заказов от −30% до +30%. Меняется количество заявок из готового пула, а не вес каждой заявки. Рядом видно «12 → … заказов».

**Ресурсы.** Галочка у машины убирает её из плана. Галочка у водителя отключает водителя, но не помечает машину сломанной: если водитель отсутствует, машина исправна, но в рейс не идёт. Поле «Остаток до ТО, км» ограничивает пробег вместе с пустой ездой и возвратом на базу. Пустое поле значит «как в наборе данных».

Пока идёт расчёт, поля блокируются. Это короткий синхронный поиск, не очередь заданий.

Готовые кнопки — авторские стресс-тесты, не статистика рынка:

| Кнопка | Что делает |
|---|---|
| Исходные условия | Все изменения нулевые |
| Рост расходов | Дороже топливо, труд и подрядчики |
| Сжатие маржи | Те же расходы, тариф клиенту −5%, заказов −20% |
| Недоступен водитель | Отключён водитель D-02 |
| Машина близка к ТО | У V-01 остаток до ТО 300 км |
| Недостаточно мощности | Отключён водитель рефрижератора D-03, полного плана нет |

Нулевой эффект тоже нормальный результат. Программа не обещает, что каждый сценарий улучшится.

### Три раздела

**Обзор.** Четыре показателя выбранного состояния: расчётный операционный результат, маржинальность, затраты, сервис. Результат — доход от выполненных перевозок минус расходы модели за смену. Это не бухгалтерская отчётность. Отрицательное число подписано как убыток в модели.

Ниже схема сети. Это условный рисунок, не навигационная карта. Сплошная линия — пробег с грузом, пунктир — пустой. Список «Все / V-01 / …» оставляет на схеме одну машину.

Таблица сравнивает A, B и C. Последняя колонка — разница C минус B. Для маржи единица «п.п.», процентные пункты. Прочерк значит, что величины нет, а не ноль.

График расходов составлен из тех же статей, что и таблица. Фиксированная зарплата и владение парком видны и у машины, которая почти не ехала.

**План перевозок.** Сверху переключатель A, B и C. У каждой машины последовательность заказов и полоса времени от 08:00 по Москве. Машина без рейса подписана: она не назначена, но фиксированные затраты сохраняются. Недоступная машина показывает причину, без выдуманного рейса.

Таблица заказов фильтруется по номеру и направлению и сортируется по номеру, сроку или выручке. Клик по строке открывает карточку. У заказа в цепочке показана стоимость всей цепочки, а не «точная себестоимость одного заказа»: общие пустые километры между заказами однозначно не делятся.

**Данные и модель.** Карточки происхождения: что синтетика, что не загружено. Допущения расчёта. Движок поиска, статус, число кандидатов и измеренное время. Кнопки «Сохранить вход» и «Сохранить результат» скачивают JSON. По нему можно повторить расчёт. «Сохранить сценарий» в шапке скачивает только параметры.

Внизу каждой страницы есть напоминание: результат — расчёт модели на выбранных данных, не подтверждённый эффект для реальной компании.

## Как читать контрольный пример

Файл `data/reference/tiny_economics_fixture.json` — две заявки и одна машина. Ожидаемые суммы лежат в `data/reference/tiny_economics_expected.json`.

| Состояние | Затраты | Результат | Пробег | Пустой пробег |
|---|---:|---:|---:|---:|
| A, исходные цены | 18 000 ₽ | 3 000 ₽ | 400 км | 200 км |
| B, топливо +25% и зарплата +10% | 20 600 ₽ | 400 ₽ | 400 км | 200 км |
| C, те же цены, одна цепочка | 14 600 ₽ | 6 400 ₽ | 200 км | 0 км |

Зарплата в B и C одинаковая, 6 600 ₽. Владение машиной тоже одинаковое, 2 000 ₽. Они не исчезают от того, что машина проехала меньше. Этот пример проверяет арифметику, а не точность рыночного прогноза.

## Проверки

Из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests
.\.venv\Scripts\python.exe -m ruff check backend scripts
npm --prefix frontend run typecheck
npm --prefix frontend test
```

На момент подготовки репозитория: pytest — 16 тестов, ruff без замечаний, проверка типов без ошибок, vitest — 3 теста, сборка интерфейса завершалась успешно.

## Чего программа не делает

Она не бронирует рейсы, не меняет зарплаты сотрудникам и не выпускает машины. Рекомендация остаётся на экране.

Не моделируются географическая карта, режим труда по нормативам, место самого ТО и покрытие сервисов. В кузове один неделимый заказ. Новая цепочка не длиннее трёх заказов. Оптимальность поиска означает «лучший среди построенных вариантов», а не лучший из всех мыслимых маршрутов. Если поиск не уложился во время, это не доказательство, что перевезти груз невозможно.

Макропоказатели Росстата и выгрузка компании не подключены.
