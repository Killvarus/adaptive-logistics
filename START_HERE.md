# Как передать пакет агенту

## Что находится в архиве

- `MVP_SPEC.md` — самостоятельное подробное ТЗ: продукт, экономика, алгоритм, UI, API, данные, структура проекта, тестирование, демонстрация.
- `AGENTS.md` — короткие постоянные правила для coding-агента.
- `data/reference/tiny_economics_fixture.json` — авторский двухзаявочный проверочный вход.
- `data/reference/tiny_economics_expected.json` — рассчитанный вручную и проверенный арифметически ожидаемый результат.
- `data/reference/README.md` — смысл и границы использования примера.

Пакет не содержит готовый frontend/backend. Он предназначен для их реализации агентом.

## Порядок

1. Помести содержимое архива в корень проектного репозитория. Если AGENTS.md уже существует, объедини правила вручную, не перезаписывая существующие инструкции без проверки.
2. Открой репозиторий в своей среде с coding-агентом.
3. Передай агенту команду ниже.
4. Прикладывай визуальные референсы дополнительно, но не вместо текстовой спецификации.
5. До публикации уточни правила чемпионата о сроке подачи и правах на код. В ТЗ отмечено расхождение публичного регламента с переданной памяткой.

## Стартовая команда

```text
Прочитай AGENTS.md и MVP_SPEC.md целиком, затем изучи текущий репозиторий.
Не ограничивайся планом: реализуй первый вертикальный срез из раздела 16.

Сначала сделай схему данных, финансовое ядро, API evaluate и рабочий
React-экран с настоящими KPI. Проверь денежную модель на примере
из data/reference. Затем добавь граф, baseline и адаптацию цепочек.

Визуальные требования находятся в разделах 11–13. Не используй внешние
LLM API, зарубежные датасеты, карты и runtime-CDN. Не создавай фиктивные
результаты и не выдавай синтетику за реальные данные компании.

Работай небольшими этапами, запускай проверки и обновляй docs/STATUS.md.
Не делай push, публичную публикацию или выбор лицензии автоматически.
```

## Самое важное при проверке результата

На одном входе B и C должны иметь одинаковые заказы и цены. Экономия должна вытекать из реальных изменений маршрута и ledger. Фиксированная зарплата не должна исчезать, когда машина проехала меньше. Любое «ТО учтено» должно подтверждаться проверкой километража с возвратом.

Если скачан только отдельный Markdown-файл, сохрани его в репозитории под именем `MVP_SPEC.md`; он самодостаточен и содержит стартовый промпт в конце.
